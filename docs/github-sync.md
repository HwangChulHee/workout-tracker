# GitHub 동기화와 Pages 배포

## fine-grained PAT 발급

1. GitHub의 **Settings → Developer settings → Personal access tokens → Fine-grained tokens**에서 새 토큰을 만듭니다.
2. **Resource owner**는 `HwangChulHee`, **Repository access**는 **Only select repositories**로 설정하고 비공개 `workout-data`만 선택합니다.
3. **Repository permissions → Contents**를 **Read and write**로 지정합니다. 필수 Metadata 읽기 권한은 GitHub에서 함께 부여합니다. 다른 저장소나 계정 권한은 추가할 필요가 없습니다.
4. 사용할 기간에 맞춰 만료일을 정하고 발급된 토큰을 앱의 **설정 → GitHub 동기화**에 직접 붙여넣습니다. 토큰을 저장소, 채팅, URL, 로그, Actions 시크릿에 입력하지 않습니다.

[GitHub 토큰 관리 문서](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)

## 첫 연결과 기기 변경

첫 연결 전에 **설정 → 내보내기**에서 현재 로컬 기록의 JSON 백업을 저장할 수 있습니다. 앱에서 **연결 및 동기화**를 선택하면 비공개 저장소와 파일 읽기 권한을 확인하고, 원격 기록을 가져오며 이 기기의 기록도 안전하게 병합할 수 있을 때 올립니다. Contents 쓰기 권한은 실제 쓰기 시 확인되므로 읽기만 허용된 토큰으로 연결하면 변경 전송 시 권한 오류가 표시됩니다.

다른 기기에서는 같은 배포 URL을 연 뒤 해당 기기에서 토큰을 입력합니다. 기기별 토큰을 발급하면 한 기기에서 사용한 토큰만 취소할 수 있습니다. 앱은 연결 시 로컬·원격 기간 파일을 읽고, 저장이 잠시 멈추거나 네트워크가 복구되면 다시 동기화합니다. **지금 동기화**로 즉시 확인할 수도 있습니다.

오프라인에서는 기록이 IndexedDB에 먼저 저장됩니다. 페이지를 닫은 동안에는 원격 동기화가 실행되지 않습니다. 최초 온라인 방문 후 앱의 정적 파일이 캐시되면 오프라인에서도 열 수 있습니다. 브라우저의 사이트 데이터를 지우면 로컬 기록과 브라우저에 저장한 토큰도 삭제됩니다.

## 충돌과 복원

- 같은 날짜에 각각 추가한 다른 종목이나 세트는 UUID를 기준으로 병합합니다. 두 기기가 새로 만든 동일 날짜 세션에는 원격 세션 UUID를 사용하고 양쪽 종목을 보존합니다.
- 같은 값을 다르게 바꾸거나 한쪽에서 삭제하고 다른 쪽에서 수정한 경우, 해당 파일의 쓰기를 중단합니다. **설정 → 충돌 해결**에서 기기와 GitHub 값을 확인하고 선택한 뒤 **선택 적용 후 동기화**를 누릅니다. 그 사이 값이 바뀌면 다시 선택해야 합니다.
- 이전에 확인한 파일 전체가 사라지거나 같은 ID가 여러 기간 파일에 있으면 자동 적용을 중단합니다. 원본 파일을 GitHub 이력에서 확인·복원한 뒤 다시 동기화하세요.
- 각 쓰기는 GitHub에 확인한 파일 SHA로 조건을 걸고 저장 뒤 재조회합니다. 네트워크 단절로 응답을 못 받아도 쓰기 의도를 기기에 남겨 동일 변경을 중복으로 올리지 않습니다.
- 월별 운동과 연별 인바디 파일은 개별 갱신됩니다. 서로 다른 기간 파일에 걸치는 날짜 변경은 원격에서 한 번에 처리되지 않습니다.
- 기기 백업은 **설정 → 내보내기**, 로컬 복원은 **설정 → 가져오기**를 사용합니다. 가져오기는 전체 파일을 먼저 검사하고 기존 날짜·ID와 충돌하는 항목을 건너뜁니다.

## 토큰 교체와 보안

기본값은 토큰을 현재 앱 실행의 메모리에만 두는 것입니다. **이 브라우저에 토큰 기억하기**를 선택하면 브라우저의 로컬 저장소에 남습니다. 같은 출처의 스크립트가 접근할 수 있으므로 XSS, 악성 확장, 기기 침해 시 노출될 수 있습니다. 공유 기기에서는 기억하기를 선택하지 마세요.

토큰이 만료되거나 권한이 바뀌면 새 토큰으로 **토큰 교체 및 동기화**를 실행합니다. **연결 해제**는 이 기기의 연결과 저장한 토큰을 제거합니다. GitHub에서 토큰을 취소하려면 GitHub 설정에서 별도로 취소해야 합니다. 로컬 기록과 동기화 기준 정보는 해당 브라우저에 보존됩니다.

프로덕션 앱은 HTTPS GitHub API에 Authorization 헤더로 요청합니다. 서비스 워커는 정적 앱 파일만 캐시합니다. Pages 자체는 공개이며 개인 파일은 비공개 저장소와 사용자의 브라우저에 있습니다.

## GitHub Pages 배포

이 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다. `main`에 푸시하면 **Workout Tracker Pages** 워크플로가 Node.js 22에서 설치, 타입 검사, 린트, 테스트, 빌드를 실행합니다. 성공하면 `dist/`만 아티팩트로 올리고 `github-pages` 환경에 배포합니다. **Actions** 탭에서 워크플로를 수동으로 다시 실행할 수 있습니다. 계정의 PAT나 운동 데이터는 배포 워크플로에 필요하지 않습니다.

배포가 성공하면 [Workout Tracker](https://hwangchulhee.github.io/workout-tracker/)를 Chrome 또는 Edge에서 엽니다. Galaxy Chrome에서는 브라우저 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 사용합니다. 새 버전이 준비되면 앱의 업데이트 버튼으로 적용합니다. [GitHub Pages 커스텀 워크플로 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 알려진 제약

- 화면 잠금이나 백그라운드 상태에서는 진동과 타이머 콜백이 지연되거나 실행되지 않을 수 있습니다. 화면으로 돌아오면 종료 예정 시각을 기준으로 남은 시간을 계산합니다.
- GitHub 서버의 요청 한도에 도달하면 지정 시간까지 대기합니다. GitHub Contents API가 파일 본문을 반환하지 않을 정도로 파일이 커지면 해당 파일의 동기화를 중단합니다.
- 인바디 수치는 장비와 측정 조건의 영향을 받습니다. 그래프와 이전 측정 비교는 관측값의 차이를 보여 줍니다.
